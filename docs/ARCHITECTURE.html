1. 전체 그림

개발 PC가 시뮬레이터로 학습 데이터를 만들고, 모델 5개와 문턱을 학습한 뒤, 실차 주행과 실제 사람 MISC로 검증합니다. 결과는 모두 버전 폴더에 쌓이고, 배포할 버전 하나를 골라 Pi에 복사합니다. 실행 중에는 Pi 혼자 10초마다 위험도를 계산해 기기를 켜고 끕니다. 폰과 HUD는 ESP32 브리지를 거쳐 P6·P5로 붙습니다 (P4 --rf). 이 경로는 구현과 시뮬레이션 시험까지 끝났고, 실제 기기를 Pi에 붙인 시험은 아직입니다. BLE 없이 돌릴 때는 P4 실행 인자 --phone, --hud가 등록을 대신합니다.

2. 시뮬레이션 → 학습 → 배포

왼쪽에서 오른쪽으로 한 번 돌리면 새 데이터셋 버전(v006)과 새 모델 버전(v007)이 생깁니다. 모든 단계가 protocol/의 계약 파일을 읽습니다. 시뮬레이터 정답(MISC)은 Oman 식으로 만들므로, 이 그림 안의 성능은 "구조가 의도대로 도는가"의 근거이고 실제 정확도는 3장에서 따로 봅니다.

3. 검증 · 보정 루프

시뮬레이터 밖의 자료 세 가지로 확인합니다. 실차 두 개(BATON, comma2k19)는 운동 분포와 확률 수준을 보고, 시뮬레이터 설정을 고치는 기준(T-23)이 됩니다. 실차 신호와 사람 MISC가 함께 있는 공개 데이터는 없어서, 실제 사람 MISC는 TU Delft 실험을 가상 주행으로 바꿔 시험합니다.

4. 단계별 입력 · 처리 · 출력

vNNN은 ml/out/runs/vNNN/입니다. 명령은 저장소 루트에서 실행합니다.

13. 기기 연결 (PRD §5 기준)

P5·P6, ESP32 브리지, 앱, HUD 모두 구현돼 있습니다 (PR #4, #5). P4·P2와 연결했고, Mac 시험(pipeline_rf_sim)과 Pi의 가상 터미널 브리지 흉내로 확인했습니다. 실제 ESP32·폰·HUD를 Pi에 붙인 시험은 아직입니다. Pi 안의 메시지는 docs/RF_MESSAGES.md, 기기 메시지와 UUID는 protocol/이 기준입니다.

구간물리 · 형식내용
Pi P6 ↔ ESP32-S3UART3 /dev/ser3 GPIO4/5 (핀 7·29), 115,200 bps 8N1. 구현, Pi 실연결 시험 전한 줄 <id>|<payload>\n, id = 연결 0~8 또는 ALL, 최대 512 B. 제어 토큰 CONNECT, DISCONNECT (ESP32 → Pi), DROP (Pi → ESP32)
ESP32-S3 ↔ 폰 · HUDBLE GATT, ESP32 = Peripheral, 광고 MSAgent-xxxx서비스 cd820001-…, RX cd820002 (Write Without Response), TX cd820003 (Notify), MTU 247, 최대 9 연결, LE Secure Connections
M00 HELLO기기 → 컨트롤러role (app / hud), dev (영구 ID), v. 연결 후 5초 안에 없으면 DROP
M01 INT컨트롤러 → 기기tier, on
M02 MOT컨트롤러 → 기기, 10 Hzax, ay (가중 가속도), 경로가 있으면 pax, pay
M03 SCR기기 → 컨트롤러on (화면), att (응시) → P4 게이트
M05 OVR기기 → 컨트롤러dev, on (수동 조작) → P4 허용도, 쿨다운
M06 PROF앱 ↔ 컨트롤러mssq, sens → P4 프로필
M07 HB양쪽, 1초seq. 5초 동안 아무것도 못 받으면 끊김
