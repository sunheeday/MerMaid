1. 전체 그림

개발 PC가 모델과 문턱을 한 번 만들어 Pi에 복사하고, 실행 중에는 Pi 혼자 10초마다 위험도를 계산해 기기를 켜고 끕니다. 브리지와 폰, HUD는 아직 없고, 그 자리는 P4 실행 인자와 로그 파일이 대신합니다.

2. 개발 PC 파이프라인 (S0~S4, 검증)

왼쪽에서 오른쪽으로 한 번 돌리면 모델 5개와 문턱이 나옵니다. 모든 단계가 protocol/의 계약 파일을 읽습니다.

3. Pi 런타임 (S6)

QNX 프로세스 4개가 메시지 전달(MsgSend / MsgReceive / MsgReply)로 이어집니다. 받는 쪽은 바로 복사하고 회신해서 100 Hz의 P1이 막히지 않습니다. 각 프로세스는 다음 단계에 연결된 뒤에야 자기 이름을 붙여서, 시작 순서는 P4 → P3 → P2 → P1입니다.

4. 10초 한 주기

P2가 1,000번째 샘플을 받는 순간부터 P4가 결정을 쓰기까지의 순서입니다. 숫자는 Pi에서 잰 값입니다.

5. 모델 입력 77개 벡터

P2가 차량 피처 71개를 만들고, P3가 폰마다 허용도(G8)와 승객 프로필(G10)을 붙입니다. 학습 데이터(dataset.npz의 X)도 같은 순서입니다. 피처 하나하나의 정의는 SPEC.md 4장.

8. 미구현 연결 (PRD §5 기준)

S7~S10에서 만들 부분입니다. 메시지 스키마와 UUID는 protocol/에 이미 있습니다.

구간물리 · 형식내용
Pi P6 ↔ ESP32-S3mini UART /dev/ser1 GPIO14/15, 115,200 bps 8N1한 줄 <id>|<payload>\n, id = 연결 0~8 또는 ALL, 최대 512 B. 제어 토큰 CONNECT, DISCONNECT (ESP32 → Pi), DROP (Pi → ESP32)
ESP32-S3 ↔ 폰 · HUDBLE GATT, ESP32 = Peripheral, 광고 MSAgent-xxxx서비스 cd820001-…, RX cd820002 (Write Without Response), TX cd820003 (Notify), MTU 247, 최대 9 연결, LE Secure Connections
M00 HELLO기기 → 컨트롤러role (app / hud), dev (영구 ID), v. 연결 후 5초 안에 없으면 DROP
M01 INT컨트롤러 → 기기tier, on
M02 MOT컨트롤러 → 기기, 10 Hzax, ay (가중 가속도), 경로가 있으면 pax, pay
M03 SCR기기 → 컨트롤러on (화면), att (응시) → P4 게이트
M05 OVR기기 → 컨트롤러dev, on (수동 조작) → P4 허용도, 쿨다운
M06 PROF앱 ↔ 컨트롤러mssq, sens → P4 프로필
M07 HB양쪽, 1초seq. 5초 동안 아무것도 못 받으면 끊김

이 파일은 docs/ARCHITECTURE.html입니다. 브라우저로 바로 열 수 있고, 외부 파일을 쓰지 않습니다.
