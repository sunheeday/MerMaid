# MerMaid 탑승객 앱 명세 v1 (Android)

> 작성 정유경 · 2026-11-19 · 2026-11-11 초안(v0.9)을 **레포 프로토콜 v1**에 맞춘 갱신판
> 기준 (값이 다르면 아래 파일이 맞음): `protocol/PROTOCOL.md`, `protocol/uuids.json`, `protocol/messages.schema.json`, `docs/RF_MESSAGES.md`, `bridge/README.md`
> 앱 코드: `apps/android/` (이준민 작성, v0.2, **컴파일·실기 시험 전**). 실기 시험 순서는 [`폰시험_체크리스트.md`](폰시험_체크리스트.md)

이 문서에서 **P1~P7은 Pi 프로세스 이름**에만 쓴다. 폰 시험 번호는 A0~A15이다.
코드 줄 번호는 `main` 7ab9768 기준이고, 경로는 `apps/android/app/src/main/java/com/mermaid/passenger/` 아래다.

## 0. 한 줄 요약

Pi(컨트롤러)가 결정하고, 앱은 세 가지만 한다.

1. 자기 상태를 Pi에 알린다 (HELLO, SCR, PROF, HB)
2. Pi의 명령을 화면에 보여 준다 (INT, MOT → 화면 가장자리 점)
3. 사용자의 수동 조작을 Pi에 전한다 (OVR)

여기에 기록용으로 하나가 더 있다 (2026-11-21 추가). 승객이 동의하면 직접 고른 멀미 점수를 Pi에 보낸다 (SYM). Pi는 주행 로그(P7)에 남기기만 하고 **정책 판단에는 쓰지 않는다.**

2026-11-23 추가: 동의했으면 폰 GPS의 **속도**도 보낸다 (GPS, 위도·경도는 보내지 않음). Pi는 모델 입력과 주행 로그에 쓴다. Pi는 이 폰의 멀미 위험 확률을 약 10초마다 보내고 (RISK), 앱은 새 **대시보드** 화면에 보여 주기만 한다.

폰은 송풍이나 HUD에 직접 명령하지 않는다. 폰이 Pi에 OVR을 보내면 Pi가 HUD에 명령한다.

```
폰 앱 ──BLE── ESP32 브리지 ──UART3── P6 통신 ── P5 기기 관리 ── P4 정책
HUD  ──BLE──┘                          ▲
                                       └ P2 피처 (MOT 10 Hz)
```

## 2. BLE 연결 규칙

### 2-1. 값

| 항목 | 값 |
|---|---|
| 역할 | 앱 = Central, ESP32-S3 = Peripheral |
| 광고 이름 | `MSAgent-xxxx` |
| 서비스 | `cd820001-2f55-4bae-8e0f-8474006c441e` |
| RX (앱 → Pi) | `cd820002-2f55-4bae-8e0f-8474006c441e`, Write Without Response, 암호화 필수 |
| TX (Pi → 앱) | `cd820003-2f55-4bae-8e0f-8474006c441e`, Notify, 암호화 필수 |
| 보안 | LE Secure Connections, Just Works. 첫 연결 때만 Android 페어링 창 |
| MTU | 연결 직후 247 요청 (한 번에 244바이트) |
| 메시지 | JSON 한 줄 + `\n`, `t` 필드로 종류 구분, 최대 512바이트 |
| 받기 | 알림 여러 개로 나뉘어 올 수 있음. `\n`이 나올 때까지 이어 붙인 뒤 해석 |
| 쓰기 | 메시지 하나 = 쓰기 한 번. Android는 쓰기를 한 번에 하나만 받으므로 앱에 보내기 줄(큐)을 둠 |
| 연결 번호 | 앱은 보지도 붙이지도 않음. ESP32와 Pi 사이에서만 씀 |
| 필드 | 스키마가 정한 필드만 보냄 (스키마는 다른 필드를 허용하지 않음). 앱은 모르는 `t`를 받으면 버림 |
| 버전 | HELLO의 `"v":1`에서 한 번만 |

### 2-2. 연결 순서 — HELLO는 암호화 뒤에

브리지(v7~v8)는 이렇게 동작한다.

- 폰이 연결하면 브리지가 먼저 보안 요청을 보낸다.
- **암호화가 끝난 뒤에만** Pi에 CONNECT를 알린다. Pi(P6)의 5초 HELLO 시계는 이때부터 돈다.
- 암호화 전에 폰이 쓴 것은 **버린다**. Write Without Response라서 폰에는 에러도 돌아오지 않는다.
- 15초 안에 암호화가 안 되면 브리지가 끊는다.
- 본딩된 폰이 다시 붙으면 저장된 키로 바로 암호화된다 (v8에서 이 경우도 CONNECT를 보내게 고침. v8은 `fix/rf-esp32-reconnect` 브랜치, `main`은 v7).

그래서 앱이 지킬 순서는 다음과 같다.

| 순서 | 앱이 하는 일 | 지켜야 할 것 |
|---|---|---|
| 1 | `connectGatt` | |
| 2 | MTU 247 요청 | |
| 3 | 서비스 검색, TX 알림 구독 | |
| 4 | **암호화(본딩) 끝날 때까지 기다림** | 첫 연결은 페어링 창에서 사용자가 확인을 눌러야 함 |
| 5 | HELLO | 암호화가 끝나고 **5초 안에**. 늦으면 P6이 DROP |
| 6 | PROF (프로필이 있으면), SCR | HELLO 전에 보내면 P6이 버림 |
| 7 | HB 1초마다 | |

지금 앱은 4번을 따로 하지 않는다 (§6 F2, 결정 필요 §8-1).

### 2-3. 살아 있음 확인

| 규칙 | 값 | 누가 |
|---|---|---|

## 3. 메시지

표기: C = 컨트롤러(Pi). 기준은 `protocol/messages.schema.json`.

| ID | t | 방향 | 언제 | 필드 (모두 필수, pax·pay만 선택) |
|---|---|---|---|---|
| M00 | `HELLO` | 앱·HUD → C | 암호화 뒤 5초 안에 1회 | role, dev, v |
| M01 | `INT` | C → 앱·HUD | Tier 상태가 바뀔 때, 재연결 직후 | tier, on |
| M02 | `MOT` | C → 앱·HUD | 그 기기의 큐가 켜진 동안 10 Hz | ax, ay, (pax, pay) |
| M03 | `SCR` | 앱·HUD → C | HELLO 직후 1회, 값이 바뀔 때 | on, att |
| M04 | | | 비어 있음. 번호를 다시 쓰지 않음 | |
| M05 | `OVR` | 앱·HUD → C | 사용자가 토글을 누를 때 | dev, on |
| M06 | `PROF` | 앱 ↔ C | 설문 완료·수정 (앱 → C), HELLO 뒤 저장된 값 회신 (C → 앱) | mssq, sens |
| M07 | `HB` | 앱·HUD ↔ C | 항상 1초마다 | seq |
| M08 | `SYM` | 앱 → C | 승객이 멀미 점수를 고를 때 (HELLO 뒤, 동의했을 때만). 회신 없음 | misc |
| M09 | `GPS` | 앱 → C | 폰이 위치를 줄 때마다, 최대 10 Hz (HELLO 뒤, 연결됨, 동의했을 때만). 회신 없음 | spd, acc, (brg, alt) |
| M10 | `RISK` | C → 앱 | 약 10초마다. 앱은 표시만 | p |

### 3-1. 필드 설명

| 메시지 | 필드 | 값 | 설명 |
|---|---|---|---|
| HELLO | role | `"app"` (HUD는 `"hud"`) | |
| HELLO | dev | 폰: 앱이 처음 만든 UUID, 63자 이하 | 프로필·허용도의 열쇠. `airflow-01`, `display-01`, `hud-01`은 폰 ID로 못 씀 |
| HELLO | v | 1 | |
| INT | tier | 1 송풍, 2 앰비언트, 3 점 찍기 | Tier 3 → 오버레이 켜기/끄기. Tier 1·2 → 상태 표시만 |
| INT | on | bool | `false`를 받으면 바로 점을 지움 |
| MOT | ax | m/s² | 전후 가속도 (가중 후). + = 앞으로 가속 |
| MOT | ay | m/s² | 좌우 가속도. + = 왼쪽으로 가속 (임시, §7 ④) |
| MOT | pax, pay | m/s² | 경로가 있을 때만, 둘이 함께. 몇 초 뒤 예측값 |
| SCR | on | bool | 화면이 켜져 있음 |
| SCR | att | bool | 화면을 보고 있음. 화면이 꺼져 있으면 항상 false. 판정 방법은 결정 필요 (§8-2) |
| OVR | dev | 대상 기기 ID | 아래 표 |
| OVR | on | bool | 수동 ON/OFF |
| PROF | mssq | 0~54 | MSSQ-Short 원점수. 소수 2자리 |
| PROF | sens | 0.5~2.0 | 설문 민감도. 소수 3자리. 앱이 계산해서 보냄 |
| HB | seq | 0 이상 정수 | |
| SYM | misc | 0~10 정수 | 승객이 직접 고른 멀미 점수 (MISC). 기준은 §3-5 |
| GPS | spd | m/s, 0 이상, 소수 2자리 | 필수. 폰 GPS의 속도 (`Location.getSpeed`) |
| GPS | acc | m, 소수 1자리 | 필수. 수평 정확도 (`getAccuracy`, 68% 반경) |
| GPS | brg | 도 0~360, 소수 1자리 | 선택. 진행 방향. 폰이 안 주면 필드를 빼고 보냄 |
| GPS | alt | m, 소수 1자리 | 선택. 고도. 없으면 뺌 |
| RISK | p | 0~1 실수 5개 배열 | 이 폰의 P(MISC ≥ 2), P(≥ 3), P(≥ 4), P(≥ 5), P(≥ 6) |

### 3-2. OVR의 `dev`

| 끄고 켤 대상 | `dev` 값 | 누가 보낼 수 있나 |
|---|---|---|
| 송풍 (공용) | `airflow-01` | 누구나 |
| 앰비언트 (공용) | `display-01` | 누구나 |
| 내 폰의 점 찍기 | HELLO에 넣은 **자기 기기 ID** | 그 폰 자신만 |
| 남의 폰 | (남의 기기 ID) | **P6이 거부** |

보낸 사람은 `dev`가 아니라 연결로 판별한다. v0.9의 `"phone"`, `"display"`, `"airflow"`는 이제 쓰지 않는다.

### 3-3. PROF

- 앱 → C: mssq와 sens만. `ev`(전기차 경험), `veh`(차 종류)는 SPEC T-17이 풀릴 때까지 보내지 않는다. 스키마가 다른 필드를 허용하지 않으므로 넣으면 안 된다.
- C → 앱: HELLO 때 Pi에 저장된 프로필이 있으면 P5가 돌려준다.
- 허용도는 메시지에 실리지 않는다. Pi만 가진다.
- 민감도 식: `sens = clip(e^(0.3·z), 0.5, 2.0)`, `z = (mssq − 12.90) ÷ 9.90` (`protocol/constants.json`).

### 3-4. HUD (참고)

| 항목 | 값 |
|---|---|
| HELLO | `{"t":"HELLO","role":"hud","dev":"hud-01","v":1}` |
| 등록 | 한 연결에 `airflow-01`(Tier 1)과 `display-01`(Tier 2)을 함께 등록 |
| SCR | 화면만. `att`는 항상 false (그래도 필드는 넣어야 함) |

### 3-5. SYM (멀미 점수, 기록 전용)

팀 합의로 추가했다 (앱 반영 2026-11-21). 모델의 정답 라벨로 쓰려고 Pi의 주행 로그(P7, SQLite)에 남긴다.

| 항목 | 내용 |
|---|---|
| 형식 | `{"t":"SYM","misc":N}`, N은 0~10 정수. 다른 필드 없음 |
| 방향 | 앱 → C 한쪽만. **C는 회신하지 않는다** |
| 쓰임 | 기록 전용. P4 정책(개입 결정)에는 쓰지 않는다 |
| 보내는 때 | HELLO 뒤(앱 상태 "연결됨")이고 **주행 기록 수집 동의가 켜져 있을 때만**. 승객이 누른 그 순간 한 번 |
| 안 보내는 때 | 동의 꺼짐, 연결 안 됨, 신호 없음(LOST). 응답이 없을 때 이전 값을 다시 보내지 않는다 |
| 점수 기준 | 0 증상 없음 · 1 약간 불편 · 2~5 어지러움·더움·두통 (약~강) · 6~9 메스꺼움 (약~강) · 10 구토 |
| M04와의 관계 | 예전 M04 MISC는 삭제된 채로 둔다 (번호를 다시 쓰지 않음). SYM은 새 번호 M08 |

### 3-6. GPS (차 속도)

| 항목 | 내용 |
|---|---|
| 형식 | `{"t":"GPS","spd":S,"brg":B,"acc":A,"alt":H}`. spd·acc 필수, brg·alt는 폰이 줄 때만. **위도·경도는 보내지 않는다** (필드 자체가 없음) |
| 방향 | 앱 → C 한쪽만. 회신 없음 |
| 보내는 때 | HELLO 뒤(연결됨) ∧ **주행 기록 수집 동의 켜짐** ∧ 위치에 속도와 정확도가 있음. 폰이 위치를 줄 때마다, 최대 10 Hz (`Proto.GPS_MIN_INTERVAL_MS` 100 ms) |
| 안 보내는 때 | 동의 꺼짐, 연결 안 됨, 신호 없음(LOST), 위치에 속도가 없음 (`hasSpeed()` false) |
| 위치 요청 | `LocationManager.GPS_PROVIDER`, 최소 간격 0 ms·최소 거리 0 m (폰이 주는 만큼). 새 라이브러리 없음. 동의·연결이 없으면 요청 자체를 하지 않음 (배터리) |
| 로그 | 줄마다 남기지 않고 1분마다 `GPS 1분: 받음 N · 보냄 M · 최근 x Hz · 속도 · 정확도` 한 줄, 시작·중지 때 한 줄 |

### 3-7. RISK (멀미 위험 확률)

| 항목 | 내용 |
|---|---|
| 형식 | `{"t":"RISK","p":[p2,p3,p4,p5,p6]}`. pk = 이 폰 승객의 P(MISC ≥ k) |
| 방향 | C → 앱. 약 10초마다 |
| 앱이 버리는 것 | p가 없음, 길이가 5가 아님, 0~1 밖의 값이나 숫자 아닌 값이 하나라도 있음 (RF 진단 로그에 `! 무시: …`) |
| 쓰임 | 대시보드 표시만. 앱은 이 값으로 아무것도 결정하지 않는다 |
| 로그 | 연결마다 첫 RISK 한 줄만 (`(이후 RISK는 대시보드에)`). 개수는 RF 진단 "RISK 받음" |

## 4. 기능 목록 F1~F18

| # | 기능 | v1 내용 |
|---|---|---|
| F1 | 권한 | 블루투스(스캔·연결), 알림, 다른 앱 위에 표시, 배터리 제한 없음, 정확한 위치 (차 속도용, 11-23 추가) |
| F2 | 연결 관리 | 등록된 브리지에 연결 → MTU 247 → 알림 구독 → 암호화 → HELLO. 포그라운드 서비스로 유지. 끊기면 자동 재연결 |
| F3 | 기기 ID | 첫 실행 때 UUID를 만들어 저장. HELLO와 자기 점 찍기 OVR에 씀 |
| F4 | 프로필 | MSSQ 설문 → 점수·민감도 계산 → PROF(mssq, sens). 설정에서 다시 응답 가능 |
| F5 | 화면 상태 보고 | 화면 ON/OFF·응시가 바뀔 때 SCR(on, att) |
| F6 | 하트비트 | 1초마다 HB. 5초 동안 아무것도 못 받으면 끊김 |
| F7 | 개입 상태 표시 | INT → 송풍·앰비언트·점 찍기 ON/OFF를 홈 화면과 상단 알림에 |
| F8 | 점 찍기 (Tier 3) | Tier 3 ON 동안 MOT 10 Hz → 다른 앱 위 투명 창에 가장자리 점 |
| F9 | 수동 조작 | 토글 → OVR(대상 기기 ID). INT가 돌아오면 그 값으로 맞춤 |
| F10 | 끊김 처리 | 5초 무수신 → 점 지움, "끊김" 표시, 재연결. 다시 붙으면 Pi가 현재 상태를 다시 보냄 |
| F11 | 연결 상태 화면 | 연결됨/끊김/연결 중, 기기 ID 앞 8자리, 마지막 수신 시각 |
| F12 | RF 진단 화면 | 주고받은 메시지를 시간순으로. "로그 복사"로 전체를 클립보드에 (§4-2) |
| F13 | MISC 버튼 | **삭제** (M04 제거). 멀미 점수 입력은 F15로 새로 만듦 |
| F14 | 자동 연결 | 한 번 등록하면 앱을 열지 않아도 차에 타면 연결. CompanionDeviceManager |
| F15 | 멀미 점수 입력 | 홈 "지금 멀미 정도" 카드에서 0~10을 누르면 SYM 전송. 주행 중에는 2분마다 알림으로 물어봄 (§4-3) |
| F16 | 주행 기록 수집 동의 | 설정의 토글 (기본 꺼짐). 꺼져 있으면 SYM·GPS를 보내지 않고 알림도 없음. 멀미 점수 기록도 저장하지 않음 (§4-3) |
| F17 | 차 속도 (GPS) | 연결됨 ∧ 동의 켜짐 동안 폰 GPS 속도를 GPS(M09)로 전송. RF 진단에 GPS 상태·실제 수신 주기 (§3-6, §4-4) |
| F18 | 대시보드 | Tier 상태·이력, 위험 확률 추이(M10), 내 멀미 점수 추이, 연결, 속도, 최근 로그를 한 화면에 (§4-5) |

음성 입력, 카메라, 마이크, 인터넷 권한은 없다.

### 4-1. 자동 연결 (F14) 방식

```
[처음 한 번]
권한 → "차 찾기" → Android 기기 선택 창(MSAgent-xxxx) → 주소 저장 + 존재 감시 등록
     → 연결 → 페어링 창 "확인" → 본딩 저장

[그 뒤 탈 때마다]
차 시동 (브리지 광고 시작)
  → Android가 등록된 브리지를 발견 → MerMaidCompanionService.onDeviceAppeared
  → LinkService(포그라운드 서비스) 시작 → 연결 → 저장된 키로 암호화 → HELLO
  → 상단 알림 "차량과 연결됨"

[내릴 때]
브리지가 안 보임 → onDeviceDisappeared → 30초 뒤에도 연결이 없으면 서비스 종료
```

| 단계 | 방법 |
|---|---|
| 앱이 꺼져 있어도 발견 | `CompanionDeviceManager.startObservingDevicePresence(주소)` → `MerMaidCompanionService` |
| 재부팅 뒤 | `BootReceiver`가 존재 감시를 다시 등록 |
| 백그라운드에서 서비스 시작 | CDM 등록 앱에 주어지는 권한 (`REQUEST_COMPANION_START_FOREGROUND_SERVICES_FROM_BACKGROUND`) |
| 브리지를 바꿨을 때 | 주소가 달라지므로 다시 등록 |
| 폰에서 "기기 지우기"를 했을 때 | 본딩이 사라져 다음 연결 때 페어링 창이 다시 뜸. 정상 |

삼성 One UI는 절전이 강해서 "배터리 제한 없음"을 권한 단계에서 안내한다.

### 4-2. 로그 복사 (F12)

RF 진단 화면의 버튼 줄은 "다시 연결 · 로그 복사 · 로그 지우기" 세 칸이다.

| 항목 | 내용 |
|---|---|
| 복사되는 것 | 지금 화면에 있는 로그 전체 (최근 300줄까지), 화면과 같은 형식 `시각 방향 내용`으로 한 줄씩 |
| 첫 줄 | `MerMaid RF 로그 · 기기 <ID 앞 8자리> · 앱 <버전> · <연결 상태> (<BLE/데모> <브리지 이름>)` |
| 안내 | "로그 N줄 복사됨". 로그가 비었으면 "복사할 로그가 없어요"만 띄우고 복사하지 않음 |
| 밖으로 나가는 것 | 없음. 사용자가 붙여 넣을 때만 폰 밖으로 나간다 |

### 4-3. 멀미 점수 입력과 동의 (F15, F16)

| 항목 | 내용 |
|---|---|
| 입력 위치 | 홈 화면 "지금 차 안" 카드 아래 "지금 멀미 정도" 카드. 0~10 버튼 (폰 세로 폭에서는 0~5, 6~10 두 줄. 480 dp 이상이면 한 줄) |
| 누르면 | 바로 SYM 전송 → 카드에 "N 기록됨 · HH:MM", 그 숫자 칸이 강조됨. RF 진단 로그에 `→ {"t":"SYM","misc":N}` |
| 누를 수 없을 때 | 동의 꺼짐 → "주행 기록 수집 동의가 꺼져 있어요" + "동의하기" / 연결 안 됨 → "차와 연결되면 기록할 수 있어요". 카드가 흐려짐 |
| 동의 안내 | 동의가 꺼진 상태에서 숫자를 처음 누르면 안내 창이 **한 번** 뜬다. "동의"를 누르면 동의가 켜지고 방금 누른 숫자가 전송된다. "나중에"를 고르면 다시 저절로 뜨지 않는다 ("동의하기"나 설정에서 켬) |
| 동의 설정 | 설정 → 주행 기록 → "주행 기록 수집 동의" 토글. **기본 꺼짐**. 폰에만 저장 (`log_consent`) |
| 2분 알림 | 조건: 연결됨 ∧ 이번 연결에서 INT를 한 번이라도 받음(= 주행 중으로 봄) ∧ 동의 켜짐. 2분마다 "지금 멀미 정도를 알려 주세요" 알림 (간격 상수 `Proto.SYM_PROMPT_MS`) |
| 알림에서 | 누르면 앱 홈의 입력 카드로 이동. 알림을 펼치면 0~10 칸이 있어 앱을 열지 않고 바로 고를 수 있음 |
| 응답이 없으면 | 아무것도 보내지 않는다. 다음 알림이 같은 자리에 다시 뜬다 |
| 알림이 멈추는 때 | 연결 끊김, 신호 없음(안전 OFF), 동의를 끔, 서비스 종료. 떠 있던 알림도 지운다 |
| 점수를 보낸 뒤 | 떠 있던 알림을 지우고 그때부터 2분을 다시 잰다 |
| 알림 채널 | "멀미 정도 묻기" (헤드업, 소리 없음, 진동). 상주 알림 채널과 따로라서 폰 설정에서 이것만 끌 수 있다 |
| 알림 권한 | 온보딩 권한 2단계(알림)와 홈의 띠를 그대로 쓴다. 알림이 꺼져 있으면 2분 알림은 안 뜨고 홈 카드 입력만 된다 |

### 4-4. 차 속도 GPS (F17)

| 항목 | 내용 |
|---|---|
| 권한 | `ACCESS_FINE_LOCATION`(+`COARSE`). 온보딩 권한 **5단계**(마지막, "나중에" 가능)와 설정 → 주행 기록 → "차 속도 (GPS)"의 "허용". 거절한 뒤 두 번째 누름은 앱 설정 화면을 연다. **백그라운드 위치 권한은 요청하지 않는다** |
| 대략적 위치만 | GPS_PROVIDER를 쓸 수 없어 속도를 보내지 않는다. 설정·RF 진단에 "대략적 위치만"으로 표시 |
| 포그라운드 서비스 | `foregroundServiceType="connectedDevice\|location"`. 위치 권한이 있으면 둘 다로, 없거나 거부되면 (Android 14+는 권한이 없으면 location 종류로 시작할 수 없음, 백그라운드 시작도 거부될 수 있음) **connectedDevice만으로** 시작. 그 뒤 앱을 열면 다시 location을 붙여 본다 |
| 켜는 조건 | 연결됨 또는 신호 없음(잠깐 끊김에 GPS를 껐다 켜지 않으려고) ∧ 동의 켜짐 ∧ 정확한 위치 권한. 차와 연결이 끝나거나(CONNECTING·IDLE) 동의를 끄면 위치 요청을 바로 뺀다. 보내기는 연결됨일 때만 |
| 데모 모드 | 권한·동의 없이 가짜 GPS 1 Hz (0 → 60 km/h 가속·정속·감속, 90초 주기). 데모 컨트롤러에만 감 |
| RF 진단 "GPS" 카드 | 권한(+ 폰 위치 꺼짐), 상태, **수신 주기 (최근 10초 실제 Hz · 시작 뒤 평균)**, 마지막 속도 km/h·정확도·몇 초 전, 받음/보냄(속도 없음 개수). 3초 넘게 안 오면 "수신 없음" |
| 저장 | 속도만 최근 30분, 1초에 하나씩 메모리에 (대시보드 그래프). 위도·경도는 읽자마자 버리고 어디에도 남기지 않는다 |

### 4-5. 대시보드 (F18)

홈 아래 "⚙ 설정 · ▤ 대시보드 · ⌁ RF 진단" 줄의 가운데에서 연다 (RF 진단과 같은 방식). 뒤로 가기는 홈. 색·글자·카드는 기존 `ui/Theme.kt`, `ui/Components.kt` 것만 쓴다. 그래프는 Compose Canvas로 직접 그림 (라이브러리 없음).

| 칸 | 내용 | 데이터 |
|---|---|---|
| 지금 차 안 | T1 송풍 · T2 앰비언트 · T3 모션 큐의 지금 상태, **이번 주행 이력** (시각, 켜짐/꺼짐, 누가: 컨트롤러 / 내가 직접 / 연결 끊김). 최근 6건, "모두 보기" | 주행 = 앱이 차와 연결을 시작한 때부터 끝낼 때까지 (중간 재연결은 같은 주행). 최대 200건 |
| 멀미 위험 | 최신 P(≥3)·P(≥4)·P(≥5) 큰 숫자, 받은 시각, P(≥2)·P(≥6). **최근 30분 꺾은선** 3개. 35초 넘게 빈 곳은 선을 끊음 | M10, 링버퍼 360개 (1시간분) |
| 내 멀미 점수 | 고른 주행의 점수 그래프(0~10, 점+선), 최근 5주행 목록(날짜·횟수·최고·평균, 누르면 그 주행), "기록 지우기" | 기기 안 파일 `files/sym_history.json`, **최근 10주행 × 300개**. 실제로 보낸 SYM만 = 동의 꺼짐이면 저장 안 함 |
| 연결 | 상태, 이번 연결 시간, 주행 시작 시각, 끊김 횟수, 신호 세기(RSSI dBm·좋음/보통/약함), 마지막 수신 | 기존 Stats + 주행 |
| 속도 (GPS) | 지금 km/h, 최근 30분 그래프, 그 아래 RF 진단과 같은 GPS 카드 | 링버퍼 1800개 (1초 1개) |
| 최근 로그 | 마지막 6줄, "전체 보기"(→ RF 진단, 뒤로 가면 대시보드), "로그 복사" (RF 진단과 같은 함수) | 기존 로그 |

대시보드 값은 멀미 점수 기록 파일 말고는 모두 메모리에만 있다 (앱 프로세스가 끝나면 사라짐). 밖으로 보내는 것은 없다.

## 5. 역할 구분

| 동작 | 폰 앱 | HUD | Pi |
|---|---|---|---|
| 점 찍기 켜기/끄기 결정 | ✗ | ✗ | P4 (폰별 위험 + 화면·응시) |
| 점 찍기 표시 | 표시 | ✗ | 명령 + 10 Hz 데이터 |
| 송풍·앰비언트 결정 | ✗ | ✗ | P4 (가장 민감한 탑승자 기준) |
| 송풍·앰비언트 표시 | 상태만 | 표시 | 명령 (HUD에 INT, 모든 폰에도 표시용 INT) |
| 수동 조작 | 내 점·송풍·앰비언트 (OVR) | 송풍·앰비언트 (OVR) | 허용도 갱신 |
| 화면 게이트 | 폰 SCR → Tier 3 | HUD SCR → Tier 2 | 적용 |
| 프로필 | 설문·계산·전송 | ✗ | 저장 (P4), 재연결 때 회신 (P5) |

폰이 여러 대일 때: 주 기기는 없다. 폰마다 따로 추론하고 폰마다 자기 점 찍기를 결정한다. 한 폰이 끊기면 그 폰만 명부에서 빠진다.
