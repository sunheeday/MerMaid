# 폰 시험 체크리스트 (Android 실기)

> 작성 정유경 · 2026-11-19 · 대상: `app/android/` v0.2 (컴파일·실기 시험 전), 브리지 v7~v8, Pi `p6_comm`·`p5_devmgr`·`rf_stub`
> 명세: [`앱명세_v1.md`](앱명세_v1.md) · Pi 실행법: `docs/RF_MESSAGES.md` §6 · 브리지: `bridge/README.md`

**번호에 대해:** 이 레포에서 P1~P6은 Pi 프로세스 이름이다. 헷갈리지 않게 폰 시험은 **A0~A11**로 부른다 (A0~A7은 작업 지시의 P0~P7과 같은 순서, A8~A11은 2026-11-21에 추가한 멀미 점수·로그 복사).

결과 칸은 시험한 사람이 채운다: 통과 / 실패 / 못 함 + 날짜, 폰 기종, 한 줄 메모.

## 준비물

| 무엇 | 내용 |
|---|---|
| 폰 | Android 12 이상 (대상 Galaxy S22+), 개발자 옵션 → USB 디버깅 |
| 맥 | Android Studio (Ladybug 이상). ESP32를 USB로 연결해 로그를 봄 |
| ESP32-S3 | 브리지 v8 권장 (`fix/rf-esp32-reconnect` 브랜치. `main`은 v7이라 본딩된 기기의 재연결이 Pi에 안 알려질 수 있음) |
| Pi | A3부터 필요. UART3 배선과 켜는 법은 `bridge/README.md` |

## 로그 보는 곳

| 어디 | 여는 법 | 무엇이 보이나 |
|---|---|---|
| 앱 RF 진단 화면 | 홈 → 오른쪽 위 연결 표시를 누름 | 상태, MTU, RSSI, 마지막 수신(초), HB 보냄/받음, TX/RX 개수, SCR 값, 메시지 로그 (→ 보냄, ← 받음, ! 알림). MOT·HB는 개수만 |
| ESP32 USB 로그 | 아래 명령 | `[BLE] id N connected, security request sent`, `security: encrypted=1 bonded=1`, `id N -> Pi`, `dropped by`, 10초마다 `[STAT]` |
| Pi P6 로그 | `p6_comm`을 띄운 터미널 | `no HELLO in 5 s, drop N`, `no message in 5 s, drop N`, `… before HELLO from N` |
| Pi P7 주행 로그 | P7 로거의 SQLite 파일 (여는 법은 Pi 쪽 문서) | `label` 표에 멀미 점수(SYM) 행 |
| Pi P5 로그 | `p5_devmgr`을 띄운 터미널 | `hello conn N <기기 ID> (app)`, `bye conn N`, `reconnect …`, `INT conn N tier T ON/OFF`, `STREAM conn N ON/OFF` |

ESP32 로그 (닫기: Ctrl+A, k, y):

```
screen /dev/cu.usbserial-* 115200
```

Pi (root, 받는 쪽부터. 터미널 3개):

```
p6_comm
p5_devmgr --state <state 폴더>
rf_stub --cycle --motion
```

Pi 없이 맥이 Pi 역할을 할 때 (A2에서 쓸 수 있음): ESP32 USB 시리얼에 아래처럼 친다.

```
0|{"t":"INT","tier":3,"on":true}
0|{"t":"MOT","ax":0.5,"ay":-1.0}
0|{"t":"INT","tier":3,"on":false}
```

## 알아 둘 것

| 항목 | 내용 |
|---|---|
| HB 빠짐 세기 | 앱 진단 화면에는 "빠진 개수" 칸이 없다. 받은 마지막 seq만 보인다. A7은 시작·끝 seq 차이로 판정한다 (명세 §8-7) |
| A2가 "1회 실패 후 통과"일 때 | 앱이 알림 구독 직후 HELLO를 보내기 때문일 수 있다 (명세 §6 F2, §8-1). 결과를 그대로 적고 코드는 따로 결정 |
| A4에서 5초를 넘길 때 | 앱은 5초 무수신이면 점은 지우지만 스스로 다시 붙지는 않는다 (명세 §8-4). 점이 사라진 시각과 다시 붙은 시각을 따로 적음 |
| A5의 att | 앱은 "잠금 해제 ∧ 오버레이 권한"으로 본다. 통화·근접 센서는 안 본다 (명세 §8-2). 통화 중에 att가 어떻게 나가는지 한 번 보고 메모하면 결정에 도움이 됨 |
| A9의 "주행 중" | 앱은 "이번 연결에서 INT를 한 번이라도 받음"을 주행 중으로 본다. Pi는 HELLO 직후 현재 상태를 INT로 보내므로 실제로는 연결 2분 뒤부터 알림이 온다. 데모 모드에서도 같다 (Pi 없이 알림 모양만 볼 때) |
| A9의 간격 | 2분은 `Proto.SYM_PROMPT_MS` 한 곳에 있다. 점수를 보내거나 연결이 잠깐 끊겼다 돌아오면 그때부터 다시 잰다 |
| P5·P6 중 하나만 다시 시작 | 서로의 상태가 어긋난다. 둘 다 다시 시작하고 폰을 다시 연결 |
| `/dev/ser3` | 한 프로그램만 열 수 있다. `p6_comm`이 떠 있으면 `echo`로 쓰지 못함 |
