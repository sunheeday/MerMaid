## 0. 기준 (결정된 것)

- **원본(raw) = 차 기준 축으로 놓인 값.** x 앞, y 왼쪽, z 위. 가속도는 중력 포함 m/s², 자이로는 rad/s(시작 시 치우침만 뺀 값).
  - 11-21 주행: 센서가 90도 돌아가 있었으므로 축 이름만 돌린 것을 원본으로 쓴다 → `~/SE_project/drive_logs/drive_1121_124459/raw_caraxis/` (`transform.json`에 기록)
  - 이후 주행: 센서를 x 화살표가 차 앞을 향하게 **다시 붙이므로** Pi가 기록한 값이 그대로 원본이다.
- **원칙: 학습 데이터와 같은 정의로 맞춘다.** 시뮬레이터의 IMU에는 "앞뒤·좌우 가속도 + (ax에만) 도로 경사 중력 + 진동 + 잡음"만 있고, 장착 기울기·센서 치우침·차체 기울어짐은 없다.
- 원본은 고치지 않고 보존한다. 보정값(무엇을 얼마나)은 주행마다 파일로 남기고, 보정된 데이터는 원본에서 언제든 다시 만든다.

## 2. 검증: 보정이 잘 되었는지 어떻게 아나

검증은 "보정에 쓰지 않은 사실"과 맞는지 보는 것이다. 단계마다 독립된 확인이 있다.

|---|---|---|---|
| **V1. 정지 값** | 보정 후 정지 구간의 평균 | 수평 (0, 0) ±0.05 m/s², 수직 9.81 ±0.05, 크기 9.81 ±0.03 | 평지 정지 |
| **V2. 다른 정지 구간** | 보정값을 구하는 데 **쓰지 않은** 평지 정지 구간에서도 V1이 성립하는가 | 같음 | 평지 정지 2곳 이상 |

## 5. 고려 사항

- **Pi(실시간)와 맥(사후)에 같은 보정이 들어가야 한다.** 학습은 보정된 값으로, 차에서는 보정 안 된 값으로 추론하면 다시 어긋난다. 기울기·방향·센서 오차는 Pi 설정(`imu_mount.json`, 치우침·눈금은 항목 추가 필요)으로, 중력 처리는 P2와 맥 도구가 같은 식을 써야 한다.
- **기울기 값은 장착할 때마다, 탑승 인원이 바뀔 때마다 달라진다.** 주행마다 출발 직전 정지 구간에서 다시 구한다.
- **GPS 속도 없이는 정밀 검증이 안 된다** (V7, V8의 결과).
- 센서 위치(무게중심에서의 거리)와 고정 상태를 기록한다.
- 사건·멀미 점수의 시각은 Pi 시계 기준이라 4단계 뒤에도 맞는다. 변환기에서 확인한다.
- **IMU 보정으로 해결되지 않는 부분:** 기울기를 빼도 Oman 점수가 50분에 3.2(실제 입력은 0~2점). 상수(K0)와 모델의 탑승 시간 의존은 모델 쪽에서 다룬다.
- 11-21의 모델 확률은 "축이 뒤바뀌고 기울기가 섞인 입력"에 대한 출력이다. 분석에는 보정 후 다시 추론한 값을 쓴다.
