## 왜 1·2번째 주행은 a=1, b=0이었나
- 보정은 라벨 달린 주행이 2개 이상 쌓인 뒤 `fit_calib.py`로 계산한다. 이번이 처음으로 2개가 된 시점.
- 자동이 아니다: 계산(맥/서버) → `collect_logs.py --push-calib vNNN --state <P4의 state 폴더>`로 Pi에 보냄 → P4가 다음 주행 시작이나 폰 등록 때 읽음.
- **주의:** `run_live.sh`는 state 폴더를 주행 폴더 안(`out/<주행>/state`)에 새로 만든다. 그래서
  ① 지난 주행 state에 넣은 보정 파일은 다음 주행이 읽지 못하고, ② 주행 번호(session, ride_no)도 매번 1로 돌아가 두 주행의 ride_id가 같아졌다.
  다음 주행에 쓰려면 주행 시작 전에 새 주행 폴더의 `state/calib/<phone>.json`에 파일을 넣어야 한다.
  근본적으로는 run_live.sh가 주행 사이에 이어지는 state 폴더를 쓰게 바꾸는 것이 맞다 (저장소 수정, 담당자와 상의).
