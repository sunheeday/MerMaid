# 주행 전 장착 보정 절차 (imu_mount.json)

> 2026-11-24 작성. 센서를 차에 **새로 붙였거나 다시 붙였을 때** 한 번 한다. 박스를 건드리지 않았으면 다시 할 필요 없다.

## 무엇을 하나

Pi의 P1은 시작할 때 `controller/config/imu_mount.json`의 R(숫자 9개)을 읽고, 샘플마다
`차 축 값 = R · 센서 값`으로 바꿔 P2(피처) → P3(모델)에 넘긴다. 기본 R은 단위 행렬(아무것도 안 돌림)이다.

센서가 기울거나 돌아가 붙어 있으면, 차가 서 있어도 앞뒤·좌우에 중력이 새어 들어와 모델이 "계속 가속하고 쏠린다"고 본다
(11-21 주행: 서 있을 때 (0.38, 0.53, 9.89)). 이 절차는 주행 전에 R을 계산해 넣어, 주행 중 모델이 처음부터 바로잡힌 값을 보게 한다.
**Pi 코드는 바꾸지 않는다.** 설정 파일만 바꾼다.

- 바로잡는 것: 장착 기울기(앞뒤·좌우), 축 방향(센서가 90도 돌아간 것 등)
- 바로잡지 않는 것: 센서 칩 치우침·눈금(1% 안팎), 도로 경사, 시간축 — 이것들은 주행 뒤 `run_calibration.py`로

## 준비

- 센서 박스를 주행 때처럼 차에 고정한다.
- **센서 축이 차의 어느 쪽을 보는지** 적어 둔다 (보드의 x, y 화살표). 중력으로는 알 수 없어 사람이 알려 줘야 한다.
  - 보드 x가 차 앞, y가 차 왼쪽이면 `--forward=+x --left=+y` (기본)
  - 11-21처럼 보드 y가 차 앞, x가 차 오른쪽이면 `--forward=+y --left=-x`
- 평평한 곳에 차를 세운다. 사람은 주행 때처럼 태운다(차체가 가라앉는 만큼도 함께 잰다).

## 순서

### 1. 정지 기록 60초 (Pi SSH)

```bash
cd /data/home/qnxuser/mermaid/rf-log
slay -f p1_acq p2_feat p3_infer p4_policy p5_devmgr p6_comm p7_logger 2>/dev/null
R=out/mount_$(date +%m%d_%H%M%S)
RF=0 LOGS=$R/logs DURATION_S=60 sh controller/qnx/run_live.sh $R 1
ls $R/logs/rides/
```

60초 동안 차를 흔들지 않는다(문 여닫기, 타고 내리기 금지). 끝나면 `.sqlite` 파일 하나가 보인다.

**(선택) 바닥 기울기 지우기:** 같은 자리에서 차 방향만 180도 돌려 세운 뒤 1번을 한 번 더 한다.
두 기록을 함께 주면 바닥 기울기가 상쇄된다. 하지 않으면 그 자리 바닥 기울기가 장착 기울기에 섞인다(1도 기울어 있으면 1도 틀림).

### 2. 맥으로 가져와 계산 (맥 터미널)

```bash
scp -r qnxuser@192.168.2.2:/data/home/qnxuser/mermaid/rf-log/out/mount_XXXX_XXXXXX ~/SE_project/drive_logs/
```

```bash
cd ml/realdata/imu_calib
.venv/bin/python make_mount.py ~/SE_project/drive_logs/mount_XXXX_XXXXXX --forward=+x --left=+y --out imu_mount.json
```

180도 돌린 기록도 있으면 두 번째 인자로 준다:
`make_mount.py <기록1> <기록2> --forward=… --left=… --out imu_mount.json`

화면에서 확인할 것:
- `전체 기울기`가 몇 도인지 (보통 0~5도). 10도가 넘으면 멈춘다 → 차가 서 있었는지, 센서가 위를 보게 붙었는지 확인
- `새 R 적용 시 … 정지 평균`이 (0, 0, 9.8 안팎)인지

### 3. Pi에 넣기 (맥 터미널 → Pi)

원래 파일을 먼저 백업한다 (Pi SSH):

```bash
cd /data/home/qnxuser/mermaid/rf-log && cp controller/config/imu_mount.json controller/config/imu_mount.json.bak_$(date +%m%d)
```

맥에서 새 파일을 보낸다:

```bash
scp imu_mount.json qnxuser@192.168.2.2:/data/home/qnxuser/mermaid/rf-log/controller/config/imu_mount.json
```

다음 `run_live.sh`부터 적용된다(P1이 시작할 때 한 번 읽는다). R이 회전 행렬이 아니면 P1이 시작하지 않고 `p1.err`에 `imu_mount: …`가 찍힌다.

### 4. 확인

- **주행 전 (선택):** 1번을 30초만 다시 하고 `make_mount.py`에 주면 `Pi가 낸 값(기록 그대로) 평균`이 (0, 0, 9.8 안팎)이어야 한다.
- **주행 뒤:** 주행 파일 meta의 `imu_mount`에 새 R이 적혀 있다(P7이 설정 파일을 그대로 적음).
  `run_calibration.py`의 기울기가 거의 0도로 나오고, V3(출발 때 ax가 +, 좌회전 때 ay와 gz가 같은 부호)가 맞으면 축 방향도 맞다.

## 되돌리기

센서를 떼거나 다른 차에 붙이면 백업한 파일로 되돌리거나 다시 이 절차를 한다.

```bash
cd /data/home/qnxuser/mermaid/rf-log && cp controller/config/imu_mount.json.bak_MMDD controller/config/imu_mount.json
```

## 주의

- 이 R은 붙인 상태마다 다른 값이라 **저장소의 `controller/config/imu_mount.json`(기본값)에는 넣지 않는다.** Pi에만 둔다.
- 다음 주행부터 Pi 기록 자체가 회전된 값이 된다. 주행 뒤 오프라인 분석은 `make_caraxis.py <주행 폴더> --forward=… --left=…`로
  `raw_caraxis/`를 먼저 만든다. 이 스크립트가 meta의 `imu_mount` R을 되돌려 축 순서만 바꾼 원본을 만들고, `run_calibration.py`가 기울기를 다시 구한다.
- `model_rerun.py`의 "B 맥 재현(센서 축)"은 Pi가 단위 행렬 R로 달렸다는 전제라, 새 R로 달린 주행에서는 A(Pi 기록)와 맞지 않는다.
